# Phase 5.5 — Identity & Schema Alignment Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Adopt a single entity-identity convention — UUIDv7 `Guid` PKs via an `AuditableEntity` base and `Guid?` audit actors — and realign the sample blog domain to the intended architecture.

**Architecture:** A new attribute-free `AuditableEntity` base in Domain carries the `Guid Id` (PK by SqlSugar naming convention) plus audit fields; `File`/`Article`/`Category` inherit it. Audit actor identity becomes `Guid?` end-to-end. Sample entities that belong to auth (`Author`) or are unused (`Tag`, junctions) are removed. UUIDv7 is generated at create time; a latent Guid-PK coercion bug in `DeleteAsync` is fixed via a small Application-layer `IdParsing` helper.

**Tech Stack:** .NET 10 / C# latest · SqlSugarCore (multi-DB: PostgreSQL default, SQLite in tests) · xUnit + AwesomeAssertions · `Guid.CreateVersion7()`.

## Global Constraints

- Dependency rule (§2): Domain → nothing (no external packages; **no `[SugarColumn]` in Domain**); Application → Domain; Infrastructure → Application+Domain; Api → Application+Infrastructure. Framework code never references `samples/*`.
- All DB access via SqlSugar ORM; zero vendor SQL. `InitTables` dev-only.
- Outbound JSON = camelCase.
- TDD: failing test first; acceptance = verification gate with evidence (§17.2).
- SQLite green ≠ Postgres correct — a live-Postgres gate is mandatory before "done" (Task 6).
- Sidecar / junction internal PKs stay `long IsIdentity`; only their **parent FK** becomes `Guid`.
- `dotnet build` is warnings-as-errors; the solution must compile after every task.

```csharp
using Struo.Domain.Query;

namespace Struo.Application.Query;

/// <summary>
/// Parses a string id to a PK CLR type. Special-cases <see cref="Guid"/> (not
/// <see cref="IConvertible"/>, so <see cref="Convert.ChangeType(object, Type)"/> throws for it).
/// Application-layer twin of Infrastructure's IdCoercion (which §2 keeps out of this layer).
/// </summary>
public static class IdParsing
{
    public static object ParseTo(string id, Type targetType)
    {
        var t = Nullable.GetUnderlyingType(targetType) ?? targetType;
        try
        {
            return t == typeof(Guid) ? Guid.Parse(id) : Convert.ChangeType(id, t);
        }
        catch (Exception ex) when (ex is FormatException or InvalidCastException or OverflowException)
        {
            throw new QueryException($"Invalid id '{id}' for type '{t.Name}'.");
        }
    }
}
```
