# StruoCMS — Phase 5.5 (Identity & Schema Alignment) Design

> Date: 2026-06-29
> Source of truth: the StruoCMS master spec (§0–§18) + Phase 0–5 specs.
> A small **pre-Phase-6 alignment**: establishes the entity-identity convention (UUIDv7 PK +
> UUID audit actor) that Phase 6 (auth/RBAC) builds on, and realigns the sample blog domain to
> the intended final architecture.
> Each phase runs its own brainstorm → write-plan (TDD) → execute-plan → verify cycle (§17.1).

## 1. Goal & scope

Adopt a single identity convention for entity collections and bind audit actors to user UUIDs,
ahead of the Phase 6 auth integration. Remove sample entities that do not belong in the intended
architecture.

**In scope:**
- `AuditableEntity` base (Domain) carrying `Guid Id` (PK) + audit fields; `File`/`Article`/`Category` inherit it.
- Entity PKs become **`Guid` (UUIDv7)**, framework-generated via `Guid.CreateVersion7()`.
- Audit actor identity becomes **`Guid?`** (`CreatedBy`/`UpdatedBy`, `ICurrentUserAccessor`).
- Sample realignment: remove `Author`, `Tag`, `ArticleTag`, `ArticleFile` and their relations; keep single `SeoOgImage`.
- Fix a latent Guid-PK bug in `ItemService.DeleteAsync` (Restrict id coercion).
- TDD coverage + live-Postgres verification gate.

**Out of scope (unchanged / deferred):**
- Real auth/session/SSO/RBAC and a `users` table — **Phase 6**. This phase only lays the UUID seam.
- A migration framework — still dev-only `InitTables`; production migrations are a later concern.
- Re-designing file relations into typed multi-file lists (per-type galleries) — **future phase**.
- **Multilingual SEO** (moving `SeoTitle`/`SeoMetaDescription`/`SeoOgImageId` into `ArticleTranslation` via a
  `SeoTranslation` base, retiring `ISeoMeta`) and the **sidecar relation expansion** it needs (relation graph
  understanding FKs on translation entities so a per-locale OG image can `deep`-expand + honor `OnDelete`) —
  **Phase 5.6**. This phase leaves SEO exactly as-is: the parent `Article.SeoOgImageId` single relation stays.
  5.6 depends on 5.5's `Guid` translation FK (`ArticleTranslation.ArticleId`).
- `FileTranslation` / `Language` / translation / junction **internal PKs** stay `long IsIdentity`.

## 2. Decisions locked in brainstorming

| Topic | Decision |
|---|---|
| Original premise | PKs were `long` (bigint), not `int`; bigint overflow is not a real risk. UUID is still adopted for the **identity convention** (no enumeration/IDOR, distributed generation, mergeable), not for overflow avoidance. |
| Entity PK type | **`Guid`**, generated with **UUIDv7** (`Guid.CreateVersion7()`) for Postgres index locality. Replaces `Guid.NewGuid()`. |
| Sidecar PKs | translation / junction **internal** PKs keep `long IsIdentity` (no table references them); only their **parent FK** becomes `Guid`. |
| Audit actor | `CreatedBy`/`UpdatedBy` + `ICurrentUserAccessor.GetCurrentUserId()` → **`Guid?`**. Stub returns `Guid.Empty` (nil UUID = system/seed actor); Phase 6 swaps in the real user id. |
| Convention enforcement | **`AuditableEntity` base class** (inheritance enforces the convention) over per-entity documentation. |
| §2 compliance | The base lives in **Domain** and carries **no `[SugarColumn]`** (Domain stays free of external packages). PK is recognised by the **`Id` naming convention**; nullability by `Nullable<Guid>` inference. |
| Author entity | Removed. The intended "author" of content is the audit user (Phase 6), not a separate sample entity. |
| Tag / ArticleTag | Removed (not used in the intended architecture). |
| File relations | `ArticleFile` + `Gallery` M2M removed (deferred to a future typed-multi-file design). Single `SeoOgImage` (already `Guid` FK) retained as the ImagePicker demo. |
| Data migration | Dev-only `InitTables`; **drop & recreate** affected tables. Existing dev DBs (PG/SQLite) must be recreated. Tests use fresh in-memory SQLite. |

## 3. The identity convention

```csharp
// src/Struo.Domain/Auditing/AuditableEntity.cs — zero external dependencies (§2)
namespace Struo.Domain.Auditing;

/// <summary>
/// Base for entity collections. PK is a UUIDv7 <see cref="Guid"/> recognised by the "Id" naming
/// convention (no SqlSugar attribute, so Domain stays package-free). The framework assigns the id
/// at create time. Audit actors are user UUIDs (Phase 6); null until a real user system exists.
/// </summary>
public abstract class AuditableEntity : IAuditable
{
    public Guid Id { get; set; }
    public DateTime CreatedAt { get; set; }
    public Guid? CreatedBy { get; set; }
    public DateTime UpdatedAt { get; set; }
    public Guid? UpdatedBy { get; set; }
}
```

- **Inherit** (`: AuditableEntity`): `File`, `Article`, `Category`. Each drops its own `Id` + four audit property declarations.
- **Do NOT inherit** (stay POCO with `long IsIdentity` PK, no audit fields): `ArticleTranslation`, `FileTranslation`, junction tables.
- `IAuditable` stays the Domain abstraction the AOP keys off; `AuditableEntity` is a concrete carrier of it.

### Two load-bearing assumptions (verified in TDD before relying on them)

1. **PK by convention:** SqlSugar CodeFirst treats an unattributed `Guid` property named `Id` as the
   primary key (Postgres `uuid`, no identity/auto-increment). The metadata scanner already falls back
   to `idProperty = "Id"` and enumerates inherited properties (`GetProperties(Public|Instance)`).
2. **Nullable inference:** `Guid?` without `[SugarColumn(IsNullable = true)]` is created as a nullable
   `uuid` column by CodeFirst.

**Fallback if either fails:** introduce a thin per-layer attributed base (Infrastructure for `File`,
sample for blog entities) carrying explicit `[SugarColumn(IsPrimaryKey = true)]` / `IsNullable`,
keeping `IAuditable` + the `Guid?` audit types unchanged. This is a localized change, not a redesign.

## 5. Sample changes (`samples/Struo.Sample.Blog/`)

**Deleted files:** `Author.cs`, `Tag.cs`, `ArticleTag.cs`, `ArticleFile.cs`.

**`Article.cs`** (`: AuditableEntity, ISeoMeta`):
- Remove own `Id` + audit declarations (now inherited).
- Remove `AuthorId` + `Author` nav + its `[CmsRelation]`.
- Remove `Tags` nav (M2M) + `Gallery` nav (M2M).
- `CategoryId`: `long?` → `Guid?`; keep `Category` nav (M2O, `OnDelete.SetNull`).
- **Keep** `SeoOgImageId` (`Guid?`) + `SeoOgImage` nav (ImagePicker, `OnDelete.SetNull`).
- Keep `Status`, `PublishedAt`, SEO fields, `Translations`.

**`Category.cs`** (`: AuditableEntity`):
- Remove own `Id` + audit declarations.
- `ParentId`: `long?` → `Guid?`; keep self-ref `Parent`/`Children` tree and O2M `Articles`.

**`ArticleTranslation.cs`** (POCO, unchanged shape):
- Keep `long IsIdentity` PK.
- `ArticleId`: `long` → `Guid` (parent FK follows the parent PK type).

## 6. Data flow (unchanged contracts)

- Outbound JSON stays camelCase. `id` is now a UUID string (e.g. `"018f..."`).
- Create: client omits `id`; repository assigns a v7 `Guid`; response `data.id` is the UUID.
- Get/Update/Delete by id: `ItemsController` passes the `string` id; `ConvertId`/`IdCoercion`
  parse it to `Guid` (already implemented). Bad UUID → existing `ArgumentException`/`QueryException` path.
- Relations: `categoryId` / `seoOgImageId` / `parentId` are UUID strings in payloads and projections.
- i18n: translation overlay keys parents by `Guid` (FK now `Guid`); `OverlayTranslationsAsync`
  already compares ids string-keyed, so it is type-agnostic.

## 7. Error handling

- Invalid UUID in a path/filter id → 400 via the existing `QueryException` flow (charset/format
  guarded before reaching SQL).
- Guid-PK + inbound `Restrict` delete: now coerces correctly → **409** when referenced (not a
  spurious 400). Covered by a regression test.
- AOP audit set on a `Guid?` column with `Guid.Empty` actor must not throw.

## 8. Testing (TDD — RED first)

Unit / integration (SQLite in-memory):
1. **PK convention:** create `Article`/`Category` → `data.id` is a parseable `Guid`, **version 7**
   (`Guid.Parse(id).Version == 7`); round-trip get/update/delete by that id.
2. **Audit actor:** after create, `createdBy`/`updatedBy` equal `Guid.Empty`; types are `Guid?`.
3. **AuditAop:** insert + update set audit columns without throwing on `Guid?`.
4. **Delete-Restrict regression:** a Guid-PK collection with an inbound `Restrict` relation →
   delete while referenced returns **409**, not 400 (constructed fixture; sample has none after realignment).
5. **Schema/metadata:** `/api/schema/article` no longer lists `author`/`tags`/`gallery`; still lists
   `category` (manyToOne) and `seoOgImage` (ImagePicker). `Author`/`Tag` collections absent.
6. **i18n round-trip:** create Article + translations under `Guid` parent FK; overlay returns correct locales.
7. **FK typing:** `categoryId`/`parentId`/`articleId` persist and filter as `Guid`.

Live Postgres verification gate (memory: *SQLite green ≠ Postgres correct*):
8. Against real PG: create `Article` → confirm `id` column is `uuid`, `category_id`/`seo_og_image_id`
   are `uuid`, `created_by`/`updated_by` are nullable `uuid`; insert order reflects v7 time-sort.
9. Confirm `article_translations.article_id` is `uuid` and the translation round-trip works on PG.

Test sweep:
10. Update existing fixtures/assertions that create `Author`/`Tag`, assume `long` ids, or assert
    `createdBy == "system"` (now `Guid.Empty`).

## 9. Risks & mitigations

| Risk | Mitigation |
|---|---|
| SqlSugar doesn't honor unattributed `Id` as PK, or `Guid?` nullability inference fails | Verified by tests 1/8 before relying on the base; documented fallback (§3) to per-layer attributed base. |
| Large test-fixture blast radius (authors/tags everywhere) | Dedicated sweep (test 10) before claiming done. |
| AOP `SetValue` on nullable `Guid` | Test 3. |
| Dev DBs hold old `long`/`text` columns | drop & recreate via `InitTables`; documented in the guide. |
